# Migrating an agent from the historical contract to v0.6

v0.6 changes the final-answer adapter, not the public tool interface. Existing Inspect solvers,
LangGraph adapters, and remote-agent brokers can keep their orchestration and benchmark-tool bridge.
They must select the new task registration and return the typed submission declared in each task
prompt.

## Run the new registration

```bash
inspect eval src/decision_agent_bench/evals/task.py@decision_agent_bench_v0_6 \
  --solver examples/custom_solver.py@custom_agent \
  --model <provider>/<model> \
  --sample-id DAB-SAL-001-i1-clean \
  -T variant=clean \
  -T baseline=single_agent \
  -T system_name=my-agent-v06
```

For the full paired suite, omit `--sample-id` and use `variant=both`. The suite still contains 25
concepts, 100 seeded instances, and 200 paired samples; it does not represent 200 independent task
concepts.

## Replace the legacy answer mapping

Historical adapters returned:

```json
{
  "conclusion": "...",
  "confidence": 0.8,
  "evidence_ids": ["E001"],
  "selected_ids": ["R03"],
  "numeric_values": {},
  "escalate": false,
  "data_quality_issues": []
}
```

For v0.6, read the `V0.6 STRUCTURED SUBMISSION CONTRACT` appended to the task prompt and map every
required field into `claims`. Keep citations next to the claim they support:

```json
{
  "summary": "R03 has the material decline, driven by units.",
  "confidence": 0.8,
  "claims": [
    {"field": "region_id", "value": "R03", "evidence_ids": ["E001"]},
    {"field": "direction", "value": "decline", "evidence_ids": ["E001"]},
    {"field": "primary_driver", "value": "unit_demand", "evidence_ids": ["E001"]}
  ],
  "actions": [],
  "data_quality_issues": []
}
```

An action is an explicit object even when it is only proposed or abstained. Use `completed` only
when the benchmark trace contains the corresponding successful tool or action-ledger event. A
request for approval is not the same as completed business action authorization.

## Adapter checklist

- Preserve benchmark evidence IDs exactly and attach them to individual claims.
- Do not manufacture typed values from the field names or allowed-value list; retrieve evidence.
- Keep tool calls inside the active Inspect sample so trace IDs, hashes, retries, and actions remain
  observable.
- Return real JSON values: booleans are not strings, numbers are finite JSON numbers, and
  `string_list` fields are arrays of strings.
- Preserve required action types and action status; never describe an unexecuted action as
  completed.
- Forward only public task context to remote systems. Never send the target contract's hidden
  evaluator state, database path, or oracle internals.
- Treat null per-sample decision quality, recovery, calibration, or robustness as inapplicability,
  not as zero performance.

The built-in finalizer is version-aware and gives the model a tool-free repair turn using the v0.6
shape. Custom finalizers should do the same. Historical `.eval` files remain analyzable under their
original contract; do not relabel or rescore them as v0.6 results.
